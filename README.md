# Provenance Guard

## Architecture Overview
When text is submitted to the system, it hits the `POST /submit` endpoint. From there, it is routed simultaneously to two distinct detection signals: an LLM-based classifier (`openai/gpt-oss-120b` via Groq) and a Python stylometric heuristics engine. The raw outputs from these signals are combined using a weighted Confidence Scoring algorithm to generate a single confidence float. This score is then mapped to a specific Transparency Label to be displayed to users. Finally, the system logs the original text's content ID, individual signal scores, combined confidence score, and attribution result into a structured JSON Audit Log before returning the payload. If a creator contests the label, the `POST /appeal` endpoint updates the content's status to `under_review` and appends their reasoning to the log.

## Detection Signals
1. **Signal 1: LLM-Based Classification (`openai/gpt-oss-120b`)**
   * **What it measures:** Semantic structure, logical flow, contextual coherence, and holistic tone.
   * **Why it was chosen:** AI models typically produce highly structured, overly formal, and perfectly aligned text. This signal detects semantic predictability. 
   * **Blind spot:** Heavily edited human text or formal academic writing might be flagged as AI due to its strict adherence to structure. Conversely, an AI explicitly prompted to be casual or incorporate typos might slip past.

2. **Signal 2: Stylometric Heuristics (Python)**
   * **What it measures:** Sentence length variance and type-token ratio (vocabulary diversity).
   * **Why it was chosen:** AI-generated text is generally uniform, showing low variance in sentence length. Human writing is naturally variable (alternating between short and complex sentences).
   * **Blind spot:** Human authors who intentionally write with rhythmic, repetitive structures (like certain poets) might trigger a false positive. 

## Confidence Scoring
The final confidence score represents genuine uncertainty rather than a binary output. It is calculated using a weighted average: `(LLM_Score * 0.6) + (Stylometric_Score * 0.4)`. A score in the middle of the spectrum (e.g., 0.50) indicates the text has conflicting traits (e.g., highly varied sentence structure but an overly formal semantic tone).

**Score Validation Examples:**
* **Example 1 (Lower Confidence / Likely Human):** Content ID `5a654236-2f06-4acc-ac93-a9c301f990b6` achieved a final score of `0.29`. The LLM score was 0.42, but the stylometric score was 0.09, heavily pulling the confidence down into the human threshold due to high structural variance.
* **Example 2 (Mid Confidence / Uncertain):** Content ID `0f13ccfe-4293-4c5d-93fd-2091ddd8f673` achieved a final score of `0.50`, falling right in the middle. The system acknowledges that the semantic and structural signals were highly ambiguous.

## Transparency Labels
The confidence score maps directly to one of three specific transparency labels designed for non-technical users:

* **High-Confidence AI (Score 0.75 - 1.00):**
  > "Text generated by AI. This content exhibits strong semantic and structural patterns consistent with artificial generation."
* **Uncertain Origin (Score 0.36 - 0.74):**
  > "Uncertain Origin. This content exhibits mixed structural and semantic traits common to both human and AI writing."
* **High-Confidence Human (Score 0.00 - 0.35):**
  > "Human-written content. This text demonstrates natural variability and stylistic coherence typical of human authorship."

## Rate Limiting
* **Limits:** `10 per minute; 100 per day`
* **Reasoning:** These limits reflect realistic usage for a platform where human creators submit chapters, articles, or poems. No standard human user needs to submit more than 10 articles in a single minute. This strict limit protects the `POST /submit` endpoint from automated scripts attempting to spam the system, run up Groq API costs, or reverse-engineer the scoring algorithm via rapid brute-force testing.

## Spec Reflection
How the spec helped: Defining the exact numerical thresholds (0.35 and 0.75) and the exact JSON payload structure in planning.md prior to coding meant that writing the Flask app was largely just translating established rules into Python, preventing feature creep.

How the implementation diverged: Initially, the plan was to just average the two signals 50/50. However, during testing, the stylometrics engine proved less reliable on very short texts (where variance cannot be accurately calculated), so the weighting was adjusted to rely more heavily on the LLM signal (60/40 split).

## AI Usage
Generating the Stylometrics Engine: Directed the AI to generate a pure Python function calculating sentence length variance and Type-Token Ratio. Revised the output to include fail-safes (returning a neutral 0.5 score) if the submitted text was too short to calculate variance properly.

Troubleshooting API and Environment Errors: Directed the AI to diagnose a recurring 401 Invalid API Key issue with the Groq client and a ModuleNotFoundError for the statistics package. Used the AI's guidance to clear the Python terminal cache and correct .env formatting, as well as replace the dropped __main__ execution block at the bottom of the Flask app to get the server running again.
