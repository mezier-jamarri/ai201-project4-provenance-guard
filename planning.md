# Provenance Guard: Architecture & Planning Specification

## Detection Signals


1.  **Signal 1: LLM-Based Classification (`openai/gpt-oss-120b` via Groq API)**
    *   **What it measures:** Semantic structure, logical flow, contextual coherence, and holistic tone.
    *   **Output format:** A float value between `0.0` (Highly likely human) and `1.0` (Highly likely AI). The model will be prompted to return a structured JSON response containing this single confidence float based on its internal evaluation.
    *   **Combination Logic:** This signal serves as the primary semantic anchor, weighted at 60% of the final combined score.
2.  **Signal 2: Stylometric Heuristics (Pure Python)**
    *   **What it measures:** Structural and statistical properties of the text, specifically sentence length variance (uniformity vs. burstiness) and type-token ratio (vocabulary diversity). 
    *   **Output format:** A float value between `0.0` (Highly variable/Human) and `1.0` (Highly uniform/AI).
    *   **Combination Logic:** This signal serves as the structural check, weighted at 40% of the final combined score.

The final confidence score is a weighted average: `(Signal_1 * 0.6) + (Signal_2 * 0.4)`.

---

## Uncertainty Representation

A confidence score of `0.60` does not mean the system is "60% sure it's AI." Instead, it represents genuine conflict or ambiguity in the text's traits—for instance, the text might have highly varied, human-like sentence structures (scoring low on Signal 2) but utilize an overly formal, predictable semantic flow (scoring high on Signal 1). 

The raw combined score is mapped to calibrated thresholds to prevent forcing binary outputs on ambiguous content:
*   **0.00 to 0.35:** Likely Human
*   **0.36 to 0.74:** Uncertain
*   **0.75 to 1.00:** Likely AI

---

## Transparency Label Design

The UI transparency label maps directly to the three threshold categories defined above. The exact text displayed to users is as follows:

*   **High-Confidence AI (0.75 - 1.00):**
    > *"Text generated by AI. This content exhibits strong semantic and structural patterns consistent with artificial generation."*
*   **High-Confidence Human (0.00 - 0.35):**
    > *"Human-written content. This text demonstrates natural variability and stylistic coherence typical of human authorship."*
*   **Uncertain (0.36 - 0.74):**
    > *"Uncertain Origin. This content exhibits mixed structural and semantic traits common to both human and AI writing."*

---

## Appeals Workflow

*   **Who can submit:** The original creator of the content (identified by `creator_id`).
*   **Information provided:** The system requires the `content_id` of the flagged text and a `creator_reasoning` string explaining why the classification is incorrect.
*   **System Action:** Upon receiving the `POST /appeal` payload, the system will:
    1. Update the content's status from `classified` to `under_review`.
    2. Write a new entry to the Audit Log that binds the appeal reasoning to the original detection scores.
*   **Human Reviewer View:** When opening the queue, a human moderator will see the raw submitted text side-by-side with the Signal 1 score, the Signal 2 score, the final confidence score, and the user's `creator_reasoning`.

---

## Anticipated Edge Cases

1.  **Heavily Edited Academic/Formal Writing:** A human author who writes extremely formal, highly structured academic papers may trigger a false positive. The strict adherence to grammar, predictable vocabulary, and rigid sentence structures will likely score high on both the stylometric heuristics (low variance) and the LLM semantic check, pushing the score into the "Likely AI" or high "Uncertain" range.
2.  **Prompt-Engineered "Casual" AI Text:** An AI explicitly prompted to "write a casual Reddit post with typos, slang, and no capitalization" will likely bypass both signals. The stylometric signal will detect the induced variance, and the LLM signal may interpret the structural flaws as genuine human error, resulting in a false negative.

## Architecture

**Narrative:**
When a text is submitted via `POST /submit`, it is simultaneously analyzed by the `openai/gpt-oss-120b` classifier (Signal 1) and the Python stylometric engine (Signal 2). These raw scores are aggregated by the Confidence Scoring logic to generate a single float, which the Transparency Labeler maps to a specific UI string. The result is logged to the Audit Log before returning the JSON payload. If contested, a `POST /appeal` request updates the text's status to `under_review` and appends the creator's reasoning to the Audit Log.

**Diagram:**
```text
(1) SUBMISSION FLOW:
User -> [POST /submit]
            │
            ├─> [Signal 1: openai/gpt-oss-120b (via Groq API)] (LLM Score)
            │
            ├─> [Signal 2: Stylometric Heuristics (Python)] (Metrics Score)
            │
            v
   [Confidence Scoring] (Combined Calibrated Score 0.0 - 1.0)
            │
            v
 [Transparency Labeler] (Maps score to specific UI Text Variant)
            │
            v
      [Audit Log] (Records Content ID, Scores, Attribution Result)
            │
            v
Response -> {content_id, attribution, confidence, label}


(2) APPEAL FLOW:
User -> [POST /appeal] (Content ID, Creator Reasoning)
            │
            v
   [Status Updater] (Updates content status to 'under_review')
            │
            v
      [Audit Log] (Logs appeal event & creator reasoning)
            │
            v
Response -> {status: "success", message: "..."}
```

## AI Usage

M3 (Submission Endpoint + First Signal):

Inputs provided: The Architecture section (diagram) and Detection Signals section (focusing on Signal 1).

Prompt request: Generate a Flask app skeleton with a POST /submit route, basic JSON logging, and the openai/gpt-oss-120b Groq API call function.

Verification: Run the Python script locally and pass test strings to the Groq API function to ensure it consistently returns a float between 0 and 1 before hooking it into the Flask route.

M4 (Second Signal + Confidence Scoring):

Inputs provided: The Detection Signals and Uncertainty Representation sections.

Prompt request: Generate the stylometric heuristic function (variance + type-token ratio) and the weighted combination logic (60/40 split).

Verification: Submit the 4 provided test cases (Clearly AI, Clearly Human, Formal Human, Casual AI) and verify that the combined float score falls into the expected threshold ranges.

M5 (Production Layer):

Inputs provided: Transparency Label Design and Appeals Workflow sections.

Prompt request: Generate the POST /appeal endpoint logic and the label mapping function that converts the final float into the exact strings specified in the spec.

Verification: Submit an appeal using a test content_id via curl and verify via the GET /log endpoint that the status successfully transitioned to under_review and the creator_reasoning is present in the log.
